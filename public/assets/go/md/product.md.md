# PRODUCT.md

**Path:** `PRODUCT.md`\
**Role:** Product intent and scope

## Purpose

Explain who the product serves, which problems it addresses, and which user journeys and outcomes
should guide implementation decisions.

## Guidelines

- Describe the intended users, their needs, and the product's core capabilities in concrete terms.
- Record agreed scope, important constraints, and explicit non-goals.
- Explain the main user journeys and how the team recognizes a successful outcome.
- Distinguish shipped behavior from proposals and assumptions that still need a decision.
- Use `GLOSSARY.md` for terminology and `DESIGN.md` for interface decisions.
- Keep build commands, agent workflows, release history, and detailed architecture in their own
  references so this document remains focused on the product.
